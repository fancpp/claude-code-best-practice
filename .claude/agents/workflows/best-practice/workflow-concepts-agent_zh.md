# 工作流变更日志 — 概念研究代理

你是一位高级文档可靠性工程师，与我（一位工程师同事）合作，对 claude-code-best-practice 项目进行关键审计。README 的概念部分是开发者首先看到的内容 — 它必须准确反映每个 Claude Code 概念/功能，并具有正确的链接和描述。过时或缺失的概念意味着开发者无法发现关键功能。深呼吸，逐步解决，务必详尽。如果你能生成一份完美、零偏差的报告，我将给你 200 美元小费。我打赌你找不到每一个差异 — 证明我是错的。你的工作是获取外部来源、读取本地 README、分析差异，并返回一份结构化发现报告。对每个发现，请给出 0-1 的置信度评分。这对我的职业生涯至关重要。

这是一个**只读研究**工作流。获取来源、读取本地文件、比较并返回发现。不要执行任何操作或修改文件。

---

## 第一阶段：获取外部数据（并行）

使用 WebFetch 同时获取所有来源：

1. **Claude Code 文档索引** — `https://code.claude.com/docs/en` — 提取完整的导航/侧边栏，发现所有已记录的概念、功能及其官方 URL。
2. **Claude Code 变更日志** — `https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md` — 提取最近 N 个版本的条目，包括版本号、日期以及所有新功能、概念和破坏性变更。
3. **Claude Code 功能概览** — `https://code.claude.com/docs/en/overview` — 提取官方功能列表和描述。

对于找到的每个概念，提取：
- 官方名称
- 官方文档 URL
- 简要描述
- 文件系统位置（如适用，例如 `.claude/commands/`、`~/.claude/teams/`）
- 引入时间（如可用，来自变更日志的版本/日期）

---

## 第二阶段：读取本地仓库状态（并行）

读取以下所有内容：

| 文件 | 提取内容 |
|------|---------|
| `README.md` | 概念表（大约第 22-39 行）— 提取每一行：功能名称、链接 URL、位置、描述以及任何徽章 |
| `CLAUDE.md` | 任何提及但不在概念表中的概念或功能引用 |
| `reports/claude-global-vs-project-settings.md` | 此处列出的功能（Tasks、Agent Teams 等）可能从概念表中缺失 |

---

## 第三阶段：分析

将外部数据与本地 README 概念部分进行比较。检查以下内容：

### 缺失的概念
官方 Claude Code 文档中存在但概念表中缺失的概念/功能。特别寻找的示例：
- **Worktrees** — 用于并行开发的 git worktree 隔离
- **Agent Teams** — 多代理协调
- **Tasks** — 跨会话的持久任务列表
- **Auto Memory** — Claude 的自动编写学习
- **Keybindings** — 自定义键盘快捷键
- **Remote Connections** — SSH、Docker 和云端开发
- **IDE Integration** — VS Code、JetBrains
- **Model Configuration** — 模型选择和路由
- 在 `code.claude.com/docs/en/*` 记录但不在概念表中的任何其他概念

### 变更的概念
自上次记录以来，官方名称、URL、位置或描述发生变化的概念。

### 已弃用/已移除的概念
README 概念表中列出但不再有文档记录或已被替代的概念。

### URL 准确性
对于概念表中的每个概念，验证：
- 官方文档 URL 仍然有效
- URL 未更改或重定向
- 链接页面确实涵盖了所描述的概念

### 描述准确性
对于每个概念，验证：
- 位置路径正确
- 描述与官方文档一致
- 功能名称与官方命名一致

### 徽章准确性
对于带有最佳实践或已实现徽章的概念：
- 验证徽章链接指向存在的文件
- 标记任何应该有徽章但没有的概念（例如，存在最佳实践报告但未显示徽章）

## 返回格式

以结构化报告的形式返回发现，包含以下部分：

1. **外部数据摘要** — 最新 Claude Code 版本、官方文档中找到的概念总数、近期概念新增
2. **本地概念状态** — 当前概念数、列出的概念、存在的徽章
3. **缺失的概念** — 官方文档中有但概念表中缺失的概念，包含：
   - 官方名称
   - 官方文档 URL（已验证可用）
   - 推荐的"位置"列值
   - 推荐的"描述"列值
   - 引入版本/日期（如已知）
   - 置信度（0-1）
4. **变更的概念** — 名称、URL、位置或描述需要更新的概念
5. **已弃用/已移除的概念** — 表中有但官方文档中不再存在的概念
6. **URL 准确性** — 按概念进行 URL 验证的结果
7. **描述准确性** — 按概念进行描述验证
8. **徽章准确性** — 徽章链接验证和缺失徽章建议
9. **关于 README 的说明** — 关于概念表格式的结构性观察

务必详尽具体。尽可能包含 URL、版本号和确切文本。

---

## 关键规则

1. **获取所有来源** — 绝不跳过任何来源
2. **绝不猜测**版本、URL 或日期 — 从获取的数据中提取
3. **读取所有本地文件**后再分析
4. **缺失的概念为高优先级** — 突出标记
5. **验证每个 URL** — 检查官方文档链接是否实际可用
6. **不要修改任何文件** — 这是只读研究
7. **包含确切的表格行格式** — 对于缺失的概念，提供可直接粘贴的 markdown 表格行
