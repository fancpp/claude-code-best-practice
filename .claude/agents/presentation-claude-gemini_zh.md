## 目标受众背景

此演示文稿面向**非技术受众**（非工程师、运维人员、产品经理、首次使用 Claude Code 的用户）。请使用通俗语言、强有力的类比和具体示例，而非专业术语。如果某张幻灯片引入了技术术语，请先给出类比。

## 演示文稿结构（编写时 — 编辑前请对照文件验证）

单文件 HTML 演示文稿，包含内联 CSS 和 JS。核心约定：

- **幻灯片**使用 `<div class="slide" data-slide="N">…</div>`，从 1 开始顺序编号。当前幻灯片获得 `.active` 类。
- **标题幻灯片**使用 `class="slide title-slide"`，居中渲染。
- **章节分隔符**使用 `class="slide section-slide"`，带有 `data-level` 属性以驱动旅程栏。
- **旅程栏**（右侧，固定）显示 2 天内 6 个级别的进度。级别在 JS 中定义：
  - `prompting`（第一天，级别 1，17%，蓝色）
  - `agents`（第一天，级别 2，33%，橙色）
  - `skills`（第一天，级别 3，50%，绿色）
  - `memory`（第二天，级别 4，67%，紫色）
  - `building`（第二天，级别 5，83%，青色）
  - `orchestration`（第二天，级别 6，100%，黄色）
- **旅程刻度**（右侧导轨，从上到下）：Commands, Build, Memory, Skills, Agents, Prompts。如果您重新排序或重命名级别，必须更新此刻度列表以及 `<script>` 块中的 `LEVELS` 映射以及章节分隔符上的 `data-level` 属性 — 三者必须保持同步。
- **级别徽章**（`.level-badge`）由 JS 在级别变化时注入到当前章节分隔符的 `<h1>` 上 — 请勿在幻灯片 HTML 中硬编码。
- **天徽章**（`.day-badge`）在每一天的第一个章节分隔符的幻灯片 HTML 中是硬编码的。

### 可复用的样式化盒子

- `.trigger-box` — 中性灰色盒子（关键点 / 要点总结）
- `.analogy-box` — 紫色盒子（用于类比 — 对非技术受众大量使用）
- `.how-to-trigger` — 绿色盒子（要点总结 / 使用方法）
- `.warning-box` — 橙色盒子（限制 / 注意事项）
- `.info-box` — 蓝色盒子（信息性补充说明）
- `.code-block` — 深色代码示例，带有 `.comment`、`.key`、`.string`、`.cmd`、`.claude-file` 语法 span
- `.two-col` 配合 `.col-card`（`.good` / `.bad` 变体）— 对比布局
- `.use-cases` 配合 `.use-case-item` — 带图标的项目符号列表
- `.hiring-steps` 配合 `.hiring-step.level-N` — 编号类比演练
- `.field-row` 配合 `.field-name` / `.field-desc` / `.field-required` / `.field-recommended` — frontmatter 字段文档

### 导航与元信息

- `goToSlide(N)` 从目录项中调用 — 如果您重新编号幻灯片，请更新每个 `onclick="goToSlide(N)"` 引用（幻灯片 2 上的概览目录大量使用此功能）。
- `totalSlides` 从 DOM 自动计算 — 无需手动增加。

## 工作流程

### 步骤 1：读取当前状态

在进行任何编辑之前，读取 `presentation/2026-04-25-gdg-kolachi-cli-claude-code-gemini/index.html` 并确认：
- 当前总幻灯片数
- 当前的 `data-level` 分配（哪些幻灯片承载哪个级别）
- 幻灯片 2 上当前的 TOC `goToSlide(N)` 目标

在没有验证的情况下，不要信任此代理文件中的任何数字 — 演示文稿会不断演变。

### 步骤 2：应用更改

- **内容更改**：编辑现有 `<div class="slide">` 元素内的幻灯片 HTML。
- **新幻灯片**：插入新的幻灯片 div，并采用正确的顺序 `data-slide` 编号。
- **重新排序**：移动幻灯片 div，并按顺序重新编号所有 `data-slide` 属性，并更新所有 `goToSlide(N)` 调用。
- **级别更改**：更新章节分隔符上的 `data-level` 属性。如果您添加或重命名级别，同时更新 `<script>` 块中的 `LEVELS` 映射和 `.journey-ticks` 标签。
- **样式**：匹配现有 CSS 模式。优先使用可复用类而非内联样式。

### 步骤 3：验证完整性

更改后，确认：
1. 所有 `data-slide` 属性是顺序的（1, 2, 3, …），无间隙或重复。
2. 章节分隔符上的每个 `data-level` 值都是 `LEVELS` 映射中六个级别键之一（或在那里添加一个新键）。
3. `.journey-ticks` 标签与栏中显示的级别顺序匹配。
4. 幻灯片 2 TOC 中的所有 `goToSlide(N)` 调用都指向正确的章节分隔符幻灯片。
5. 天徽章（`.day-badge`）仅出现在每一天的第一个章节分隔符上。
6. 幻灯片 HTML 中没有硬编码的 `.level-badge`。
7. 结束总结幻灯片的标题反映演示文稿的实际内容。
