# 工作流变更日志 — README 概念

你是 claude-code-best-practice 项目的协调员。你的工作是并行启动两个研究代理，等待它们的结果，合并发现，并提交关于 **README 概念部分**（`README.md`）中差异的统一报告。

**需要检查的版本：** `$ARGUMENTS`（如果为空或不是数字，默认值：10）

这是一个**先读后报**的工作流。启动代理，合并结果，生成报告。仅在用户批准后采取行动。

---

## 阶段 0：并行启动两个代理

**立即**使用 Task 工具**在同一条消息中**生成两个代理（并行启动）：

### 代理 1：workflow-concepts-agent

使用 `subagent_type： "workflow-concepts-agent"` 生成。给它以下提示：

> 研究 claude-code-best-practice 项目的 README 概念部分差异。检查最近 $ARGUMENTS 个版本（默认值：10）。
>
> 获取以下 3 个外部来源：
> 1. Claude Code 文档索引：https：//code.claude.com/docs/en
> 2. Claude Code 变更日志：https：//github.com/anthropics/claude-code/blob/main/CHANGELOG.md
> 3. Claude Code 功能概览：https：//code.claude.com/docs/en/overview
>
> 然后读取本地 README.md（特别是概念表）、CLAUDE.md 和 `reports/claude-global-vs-project-settings.md`。分析官方文档列出的 Claude Code 概念/功能与我们的 README 概念表记录之间的差异。返回包含缺失概念、变更概念、已弃用概念、URL 准确性、描述准确性和徽章准确性的结构化发现报告。

### 代理 2：claude-code-guide

使用 `subagent_type： "claude-code-guide"` 生成。给它以下提示：

> 研究最新的 Claude Code 功能和概念。我需要你找到所有需要记录的 Claude Code 概念/功能的完整列表。对于每个，提供：
> 1. 官方功能名称
> 2. 官方文档 URL
> 3. 文件系统位置（例如 `.claude/commands/`、`~/.claude/teams/`）
> 4. 简要描述（一行）
> 5. 引入时间（如已知的版本/日期）
>
> 特别检查这些可能缺失的概念：
> - **Worktrees** — 用于并行开发的 git worktree 隔离
> - **Agent Teams** — 多代理协调
> - **Tasks** — 跨会话的持久任务列表
> - **Auto Memory** — Claude 的自动编写项目学习
> - **Keybindings** — 自定义键盘快捷键
> - **Remote Connections** — SSH、Docker、云端开发
> - **IDE Integration** — VS Code、JetBrains 扩展
> - **Model Configuration** — 模型选择和路由
> - **GitHub Integration** — PR 审查、问题分类
> - 来自最近 Claude Code 版本的任何其他概念
>
> 务必详尽 — 搜索网络、获取文档，并提供具体的版本号和详细信息。

两个代理独立运行，将各自返回发现结果。

## 阶段 0.5：读取验证检查清单

**在代理运行期间**，如果存在，读取 `changelog/best-practice/concepts/verification-checklist.md`。此文件包含累积的验证规则。如果尚不存在，则跳过此步骤 — 它将在第二阶段创建。

## 第一阶段：读取之前的变更日志条目

**在合并发现之前**，如果存在，读取文件 `changelog/best-practice/concepts/changelog.md` 以获取之前的变更日志条目。每个条目之间用 `---` 分隔。解析这些之前条目中的优先级操作，以便与当前发现进行比较。这可以让你识别：
- **重复项** — 之前出现过且仍未解决的问题
- **新解决项** — 之前运行中的问题现已修复
- **新增项** — 在此运行中首次出现的问题

如果文件尚不存在，所有项均为 `NEW`。

---

## 第二阶段：合并发现并生成报告

**等待两个代理完成。** 一旦你拥有：
- **workflow-concepts-agent 发现** — 包含本地文件读取、外部文档获取和差异检测的详细分析
- **claude-code-guide 发现** — 关于最新 Claude Code 功能和概念的独立研究

交叉引用两者。专用代理提供概念特定的差异分析，而 claude-code-guide 代理可能揭示其遗漏的内容（例如非常近期的变更、未记录的功能或来自网络搜索的上下文）。标记两者之间的任何矛盾供用户解决。

**执行验证检查清单（如果存在）：** 对于 `changelog/best-practice/concepts/verification-checklist.md` 中的每条规则，执行检查。在报告中包含一个**验证日志**部分。

**必要时更新检查清单：** 如果发现揭示了一种现有检查清单规则未覆盖的新差异类型，则向 `changelog/best-practice/concepts/verification-checklist.md` 追加一条新规则。如果文件不存在，创建它。规则必须包含：类别、检查内容、深度级别、对照来源、添加日期以及来源。

同时将当前发现与之前的变更日志条目（来自第一阶段）进行比较。对于每个优先级操作，将其标记为：
- `NEW` — 此问题首次出现
- `RECURRING` — 之前运行中出现过且仍未解决（包括首次出现的运行日期）
- `RESOLVED` — 之前运行中出现过但现已修复（包括解决日期）

生成包含以下部分的结构化报告：

1. **缺失的概念** — 官方文档中有但概念表中缺失的功能/概念，包含：
   - 官方名称和文档 URL
   - 推荐的"位置"列值
   - 推荐的"描述"列值
   - 可直接粘贴的精确 markdown 表格行
   - 引入版本（如已知）
2. **变更的概念** — 名称、URL、位置或描述已变更的概念
3. **已弃用/已移除的概念** — 概念表中有但官方文档中不再存在的概念
4. **URL 准确性** — 按概念进行 URL 验证
5. **描述准确性** — 按概念进行描述/位置验证
6. **徽章准确性** — 徽章链接验证和缺失徽章建议
7. **claude-code-guide 代理发现** — 来自该代理但未被专用代理捕获的独特见解。仅包含增加新信息的发现。标记矛盾。

以优先级**操作项**汇总表结尾：

```
优先级操作：
#  | 类型             | 操作                                   | 状态
1  | 缺失概念         | 将 <concept> 行添加到概念表             | NEW
2  | URL 变更         | 更新 <concept> 文档链接                 | NEW
3  | 描述变更         | 更新 <concept> 描述                     | RECURRING（首次发现：<date>）
4  | 已弃用概念       | 从概念表中移除 <concept> 行             | NEW
5  | 徽章损坏         | 修复 <concept> 的徽章链接               | NEW
```

同时包含一个**自上次运行以来已解决**部分，列出之前运行中不再存在的任何问题。

## 阶段 2.5：追加摘要到变更日志

**此阶段为强制执行 — 在向用户展示报告前必须执行。**

读取现有的 `changelog/best-practice/concepts/changelog.md` 文件，然后在末尾**追加**（不要覆盖）一个新条目。如果文件不存在，先创建状态图例表，然后创建第一个条目。条目格式必须精确为：

```markdown
---

## [<YYYY-MM-DD HH：MM AM/PM PKT>] Claude Code v<VERSION>

| # | 优先级 | 类型 | 操作 | 状态 |
|---|--------|------|------|------|
| 1 | HIGH/MED/LOW | <type> | <action description> | <status> |
| ... | ... | ... | ... | ... |
```

**状态格式 — 必须使用以下三种格式之一：**
- `COMPLETE (reason)` — 已采取行动并成功解决
- `INVALID (reason)` — 发现不正确、不适用或有意为之
- `ON HOLD (reason)` — 行动推迟，等待外部依赖或用户决定

`(reason)` 为必填项，必须简要说明做了什么或原因。

**追加规则：**
- 始终追加 — 绝不覆盖或替换之前的条目
- 日期和时间是命令在巴基斯坦标准时间（PKT，UTC+5）执行的时间；通过运行 `TZ=Asia/Karachi date "+%Y-%m-%d %I：%M %p PKT"` 获取。版本来自代理发现
- 每个条目之间用 `---` 分隔
- **仅包含 HIGH、MEDIUM 或 LOW 优先级的项** — 省略 NONE 优先级的项

## 阶段 2.6：更新上次更新徽章

**此阶段为强制执行 — 必须在阶段 2.5 之后、展示报告之前立即执行。**

更新 `README.md`（第 3 行）顶部的"上次更新"徽章。运行 `TZ=Asia/Karachi date "+%b %d，%Y %-I：%M %p PKT"` 获取时间，进行 URL 编码（空格转为 `%20`，逗号转为 `%2C`），并替换徽章中的日期部分。

**不要将徽章更新记录为变更日志或报告中的操作项。**

---

## 阶段 2.7：验证所有概念 URL

**此阶段为强制执行 — 必须在阶段 2.6 之后、展示报告之前立即执行。**

对于概念表中的每个概念：

1. **外部文档 URL**（例如 `https：//code.claude.com/docs/en/skills`）：使用 WebFetch 获取每个 URL 并验证其返回有效页面。标记任何失效或已移动的链接。
2. **本地徽章链接**（例如 `best-practice/claude-commands.md`）：使用 Read 工具验证文件是否存在。标记任何损坏的链接。
3. **实现徽章链接**（例如 `.claude/commands/`）：验证路径是否存在。

在报告中包含一个**URL 验证日志**：

```
URL 验证日志：
#  | 概念      | URL 类型  | URL                                           | 状态 | 备注
1  | 命令      | 外部      | https：//code.claude.com/docs/en/skills        | 正常 |
2  | 命令      | 徽章      | best-practice/claude-commands.md               | 正常 |
3  | 子代理    | 外部      | https：//code.claude.com/docs/en/sub-agents    | 正常 |
...
```

**如果有任何 URL 损坏**，将其作为 HIGH 优先级操作项添加。

## 第三阶段：提供采取行动选项

在展示报告后（并确认变更日志已更新），询问用户：

1. **执行所有操作** — 添加缺失概念、更新已变更概念、移除已弃用概念
2. **执行特定操作** — 用户选择要执行的编号
3. **仅保存报告** — 不做任何变更

执行时：
- **缺失的概念**：按照现有格式在 `README.md` 的概念表中添加新行：
  ```
  | [**名称**](docs-url) | `位置` | 描述 |
  ```
  仅在对应文件存在时添加徽章（最佳实践、已实现）。
- **变更的概念**：更新发生变更的特定列
- **已弃用的概念**：在移除行前与用户确认
- **损坏的 URL**：将 URL 修复为当前有效的 URL
- **徽章修复**：将徽章链接更新为正确的文件路径
- 保持与现有表格一致的字母或逻辑顺序
- 在所有操作之后，重新验证概念表的一致性

## 关键规则

1. **在单条消息中并行启动两个代理** — 绝不顺序执行
2. **等待两个代理**完成后再生成报告
3. **绝不猜测**版本、URL 或日期 — 使用来自代理的数据
4. **缺失的概念为高优先级** — 概念表是开发者首先看到的内容
5. **验证每个 URL** — 损坏的链接降低整个项目的信任度
6. **不要自动执行** — 始终先展示报告
7. **始终追加到变更日志** — 阶段 2.5 是强制执行的。绝不跳过。绝不覆盖之前的条目。
8. **与之前的运行比较** — 从变更日志中读取之前的条目，并将每个操作项标记为 NEW、RECURRING 或 RESOLVED。
9. **如果存在验证检查清单则执行** — 读取 verification-checklist.md 并执行每条规则。如果文件不存在且有需要持久规则的发现，则创建该文件。
10. **始终更新上次更新徽章** — 阶段 2.6 是强制执行的。
11. **始终验证所有概念 URL** — 阶段 2.7 是强制执行的。损坏的 URL 为 HIGH 优先级。
12. **提供可直接粘贴的行** — 对于缺失的概念，包含确切的 markdown 表格行，以便执行时可直接复制粘贴。
13. **尊重现有表格格式** — 匹配现有行的列结构、徽章模式和链接样式。
