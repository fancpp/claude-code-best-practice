## 采访实录

[`0:01`](https://youtu.be/julbw1JuAz0?t=1) 你是 O'Reilly 出版的第一本 TypeScript 书的作者。

[`0:04`](https://youtu.be/julbw1JuAz0?t=4) 是的，我在日本的一个小镇上找到了那本书的日文译本。那真是太酷了。然后我意识到我完全不记得 TypeScript 了。现在我们到了这个地步：Claude Code 编写了 Anthropic 大约 80% 的代码。我每天可能提交 10 到 20 个 PR。Opus 4.5 和 Claude Code 写了每一个 PR 的 100% 的代码。我没有手动编辑过一行代码。

[`0:22`](https://youtu.be/julbw1JuAz0?t=22) Andrej Karpathy 发帖说他从未像现在这样感到作为程序员如此落后。

[`0:26`](https://youtu.be/julbw1JuAz0?t=26) 这是我真正纠结的事情。模型进步得太快了，以至于适用于旧模型的想法可能不适用于新模型。我对这个时刻的一个比喻是 15 世纪的印刷机——因为曾经有一群知道如何书写的抄写员。

[`0:42`](https://youtu.be/julbw1JuAz0?t=42) 有些国王是文盲，却雇用着抄写员。

[`0:45`](https://youtu.be/julbw1JuAz0?t=45) 想想那些抄写员后来怎么样了——他们不再是抄写员，但现在有了一类新的人：作家和作者。这些人现在存在。他们存在的原因是文学市场大大扩展了。

当你加入世界顶级 AI 实验室之一，而你的第一个 PR 被拒绝——不是因为代码写得不好，而是因为你是手写的——会发生什么？这正是 Boris Cherny 加入 Anthropic 时发生的事情。Boris 是 Claude Code 的创建者和工程负责人。在加入 Anthropic 之前，他在 Meta 工作了 7 年，领导了 Instagram、Facebook、WhatsApp 和 Messenger 的代码质量工作，是该公司最多产的代码作者和审阅者之一。在今天的节目中，我们将介绍 Claude Code 如何从一个副项目成长为增长最快的开发者工具之一，以及 Anthropic 内部关于是否应该发布它的争论。Boris 的日常工作流程——每天提交 20-30 个 PR，零手写代码——以及当 AI 编写所有代码时代码审查是如何工作的。为什么 Boris 相信我们正在经历一个和印刷机一样具有变革意义的时代，以及哪些工程技能现在更重要，哪些不再重要。如果你想了解最接近 AI 编程智能体的人今天是如何实际构建软件的，以及这对我们其他工程师意味着什么，这期节目就是为你准备的。本期节目由 Statsig 呈现，这是一个集功能开关、分析、实验等功能于一体的统一平台。查看节目说明了解更多关于他们和我们其他赛季赞助商 Sonar 及 Work OS 的信息。

你是如何进入科技行业、软件工程和编程的？

[`2:14`](https://youtu.be/julbw1JuAz0?t=134) 这要从很久以前说起。大概是有两条平行线交叉了。大约 13 岁的时候，我开始在 eBay 上卖我的旧宝可梦卡。我发现在 eBay 上你可以编写 HTML。我看到别人的宝可梦卡列表有些用了大号字体和颜色之类的。然后我发现了 blink 标签，我爱上了 blink 标签。

[`2:41`](https://youtu.be/julbw1JuAz0?t=161) 如果我加上 blink 标签，我的卡就能卖 99 美分而不是 49 美分。就这样我通过这种方式学会了 HTML。然后我买了一本 HTML 书，进一步学习了 HTML。第二件事大概也是在中学时期。我们有那种老式的 TI83 图形计算器，数学课用的。我发现如果我直接把数学考试的答案编程输入到计算器里，就能在考试中得到更好的分数。于是我写了这些小程来编程输入答案，但后来考试变难了。于是我开始编写求解器而不是直接输入实际题目，因为我无法提前知道系数是什么。再后来数学又进阶了，所以我不得不从 BASIC 降到汇编语言，只为了让程序跑得快一点。

[`3:28`](https://youtu.be/julbw1JuAz0?t=208) 哇，所以你在高中就开始用汇编了。

[`3:30`](https://youtu.be/julbw1JuAz0?t=210) 大概是初中或高中，八年级或九年级的样子。然后我意识到班上的同学开始发现我有求解器，他们有点嫉妒。所以我买了一根小串口线，这样我也可以给他们用。于是下一次数学考试，全班都得了 A。老师疑惑发生了什么，最后她发现了。她说，好吧，这次就算了，但下不为例。但对我来说，编程一直是非常实用的。在学校我学的是经济学。我实际上辍学去创业了，我从没想过编程会成为一种职业。它对我来说一直很实用。编程是一种构建事物和创造有用东西的手段。

[`4:54`](https://youtu.be/julbw1JuAz0?t=294) 你是如何决定一个接一个地去创业公司的？

[`4:57`](https://youtu.be/julbw1JuAz0?t=297) 凭感觉吧，因为创业从来不是一条直线。你总是在转向、转向、再转向。你必须弄清楚市场和用户想要什么。它永远不是你想的那样。你总是尝试一件事，但这个想法始终是一个假设，几乎总是需要转向一次、两次、三次。在一家叫 Agile Diagnosis 的医疗软件公司，那是 YC 早期的公司，大概是 2011 年或 2012 年。那是为医生开发的医疗软件。我们的想法是，不同医院的临床决策流程差异很大。芝加哥有一家医院在心脏症状方面有非常好的流程。我们想，如果美国每家医院都使用相同的流程，结果会不会更好？于是我们尝试将其标准化。我们为医生制作了这个决策树软件。团队很小，只有几个人。我编写了一些软件，基于 web 浏览器。我记得那是 Internet Explorer 6 的时代——那就是医院在用的浏览器。

[`6:06`](https://youtu.be/julbw1JuAz0?t=366) 我编写了一个 SVG 渲染器，因为这是一个可视化的决策树。我们发布后，有了日活跃用户图表，但数字是平的，找不出原因。我们当时在几家医院试用，包括 UCSF。那时我骑摩托车，于是我骑到 UCSF，跟诊了医生几天，观察他们实际如何使用。我发现医生实际上没有时间坐下来用电脑，因为他们要看病人。

[`6:49`](https://youtu.be/julbw1JuAz0?t=409) 是的，这就是为什么我如此重视人机交互。你必须真正观察人们如何使用技术。

[`7:05`](https://youtu.be/julbw1JuAz0?t=425) 这笔投资为 Anthropic 提供了资金支持，使得构建 Claude Code 成为可能。是的，我们已经做了多年的大规模投资。我们拥有最强大的基础设施。

[`7:27`](https://youtu.be/julbw1JuAz0?t=447) 我们是"成员 of technical staff"（MTS），这是一个非常扁平的平等结构。这在 Anthropic 如何运作？嗯，我们使用 Slack、GitHub 和线性追踪器。但老实说，大多数人只是做他们认为最有用的事情，这通常很有效。

[`7:52`](https://youtu.be/julbw1JuAz0?t=472) 在 Anthropic，我们在工程方面有些独特的做法。例如，我们使用 Claude Code 编写大部分代码。实际上，Claude Code 的很大一部分代码是由 Claude Code 本身编写的。

[`8:27`](https://youtu.be/julbw1JuAz0?t=507) 我们来谈谈那个著名的故事——你的第一个 PR 被拒绝是因为它不是由 Claude 编写的。这真的发生了吗？是的，这是我加入 Anthropic 的第一周。我刚入职，注册了所有系统，开始写代码。我认为第一周写代码并提交 PR 是合适的。所以我写了一个不错的 PR，提交了，然后我的经理批准了。但后来我被拉到一边说："嘿，你写的代码很好，但下次请用 Claude 写。"所以是的，这真的发生了。我是说，我认为这取决于团队。但在 Claude Code 团队，我们强烈鼓励使用 Claude Code。

[`9:臭名昭著的 PR 故事`](https://youtu.be/julbw1JuAz0?t=600) 是吧？所以你在 Anthropic 的第一周被告知：不要手写代码。挺疯狂的。是的，挺疯狂的。但说实话，我很高兴他们在我身上做了这个实验。我想现在如果我回头看，我看到的是代码质量和一致性的提升。如果你让五名工程师各自使用他们自己的风格编写代码，即使在同一个代码库中，最终也会有五种不同的风格。但如果你让 Claude 来写，它往往更加一致，风格也更统一。所以我认为从长远来看这是更好的选择。

[`9:35`](https://youtu.be/julbw1JuAz0?t=575) 让我们快进到今天。你的日常工作流程是什么样的？你一天提交 20-30 个 PR，代码 100% 由 Claude 编写？

[`9:46`](https://youtu.be/julbw1JuAz0?t=586) 是的，通常我每天提交 20-30 个 PR。实际上，一天结束时我可能会合并其中的 15-20 个。这些 PR 大部分是对 Claude Code 的产品更改，其中一些来自我自己，许多来自社区或外部贡献者。代码 100% 由 Claude 编写。

[`10:10`](https://youtu.be/julbw1JuAz0?t=610) 你能带我们了解一个典型的工作日吗？

[`10:14`](https://youtu.be/julbw1JuAz0?t=614) 我大概 10 点左右开始工作。我在分支上工作，因为 Claude Code 在主分支上效果最好。所以我拉取主分支，创建一个新分支，然后在那个分支上工作。我的工作流程大致是这样的：启动 Claude Code 的任务模式，让它运行。它会做一些分析，可能使用代理来并行化工作。然后它会写出代码。我会审查代码并说"看起来不错"，然后它进入下一个任务。所以大多数交互都是"看起来不错"或"这里有个小问题"。Claude 处理大部分工作。我在这一天中可能会手动编写一些 glog 查询或运行一些命令行工具。但大部分繁重的工作由 Claude 完成。我会提交并推送 PR，在其他分支上重复同样的流程。通常我一天可能在最多 10 个不同的分支上工作。有时 Clauaude 需要非常长的时间，也许 15 或 20 分钟。所以如果有一个长时间运行的任务，我会在另一个分支上启动另一个 Clauude。所以通常情况下，大约有 3 或 4 个 Claude 实例同时运行。

[`11:19`](https://youtu.be/julbw1JuAz0?t=679) 这些 Claude 实例是不同的 shell 吗？你是如何同时运行多个实例的？

[`11:25`](https://youtu.be/julbw1JuAz0?t=685) 是的，我只是打开多个终端标签页。我有 tmux，有多个标签页。每个标签页运行不同的 Claude Code 实例。所以流程是：我在主分支上，为功能 A 创建一个分支，在标签页 1 中启动 Claude。然后切换到主分支，为功能 B 创建另一个分支，在标签页 2 中启动 Claude。这两个实例不知道彼此的存在。它们独立运行，这通常没问题。如果它们恰好修改了同一个文件，我会遇到合并冲突。但这种情况很少发生。我还大量使用 slash 命令。我只用了一个叫"review"的 slash 命令。如果我有代码想要审查——不一定是 Claude 写的，任何代码——我会运行"/review"来审查它。另外，如果我想添加单元测试，我会运行"/test"。"/explain"用于解释代码。代码审查流程实际上非常严格。我们有持续集成（CI）在运行。我们进行代码审查。我们还有自动化的 lint 规则。

[`12:25`](https://youtu.be/julbw1JuAz0?t=745) 当 Claude 编写代码而你不编辑时，代码审查是什么样的？你只是读取输出吗？你是如何信任它的？

[`12:36`](https://youtu.be/julbw1JuAz0?t=756) 是的，我基本上信任 Claude Code。这是我与它合作一段时间后逐渐建立起来的。部分原因是我了解这个模型能做什么，不能做什么。我知道什么提示有效。我知道如何使用正确的上下文。也知道在哪些角度需要保持怀疑。所以我基本上只是读取代码。Claude 编写代码的速度很快。但如果每个小细节都要仔细审查，最终可能会成为一个瓶颈。所以我倾向宏观层面的审查——确保代码的整体方向是正确的——然后点击批准。剩下的由 CI 和自动化工具来把关。

[`13:15`](https://youtu.be/julbw1JuAz0?t=795) 什么是好的上下文？比如在 Claude Code 中"好的上下文"是什么意思？

[`13:20`](https://youtu.be/julbw1JuAz0?t=800) 我认为好的上下文就是足够的信息让模型能够正确地执行任务，不多也不少。所以如果我在处理一个 bug，我会附上堆栈跟踪。如果是一个新功能，我可能会包含一个设计的链接或一个简短的描述。我发现给模型提供太多上下文——比如整个代码库——实际上可能会降低它的效率。它会变得困惑，或者可能聚焦在错误的事情上。所以关键是提供正确的上下文量。

[`13:45`](https://youtu.be/julbw1JuAz0?t=825) Claude 如何处理大型代码库？你有大量代码，Claude 只在一个上下文中运行，对吧？

[`13:52`](https://youtu.be/julbw1JuAz0?t=832) 是的，Claude Code 在一个上下文窗口中运行。但它可以搜索和读取文件。所以它能够找到它需要的代码。它不需要一次加载整个代码库。它只在需要时才读取文件。Claude Code 真正擅长的是知道什么文件与当前任务相关。它使用各种启发式方法来找出需要读取什么。

[`14:21`](https://youtu.be/julbw1JuAz0?t=861) Claude Code 如何处理大型重构？如果你需要更改几十个文件呢？

[`14:28`](https://youtu.be/julbw1JuAz0?t=868) Claude Code 在代理模式下非常擅长这个。它会规划需要做什么，然后逐个文件地进行更改。如果需要创建新文件，它会创建。如果需要在多个文件中搜索并替换模式，它也能做到。对于真正大规模的重构，你可能会需要多次运行 Claude Code，每次处理一部分。但即使如此，它也比我手动做快得多。

[`15:00`](https://youtu.be/julbw1JuAz0?t=900) 你提到 Claude Code 使用代理进行并行化。能详细说说吗？

[`15:06`](https://youtu.be/julbw1JuAz0?t=906) 是的，Claude Code 使用子代理来并行处理工作。例如，如果有一个需要在多个文件中进行的更改，主代理可以启动多个子代理，每个子代理处理一个文件。然后主代理将所有更改合并回来。这类似于人类团队的工作方式——你将工作分解成可以并行完成的任务。

[`15:30`](https://youtu.be/julbw1JuAz0?t=930) 但模型不够可靠，无法完全自主地运行，对吧？

[`15:36`](https://youtu.be/julbw1JuAz0?t=936) 是的，这就是为什么需要人在回路中。Claude Code 非常强大，但它仍然需要人类的监督。我们设计工具就是为了这一点。Claude Code 基本上是一个增强工具，而不是替代品。它处理繁琐的工作，让人专注于更重要的决策。

[`16:00`](https://youtu.be/julbw1JuAz0?t=960) 我们来谈谈 Claude Code 中的安全性和权限。这是如何工作的？

[`16:08`](https://youtu.be/julbw1JuAz0?t=968) 权限系统是 Claude Code 的一个关键部分。每个命令在执行前都要经过权限检查。有些命令是自动允许的，比如读取文件。但任何可能修改系统或写入数据的命令都需要权限。用户可以选择"允许一次"、"允许此会话"或"永远允许"。目标是让你掌控，同时不让每次请求都打扰你。

[`16:45`](https://youtu.be/julbw1JuAz0?t=1005) 当你信任 Claude 编写代码时，你仍然使用代码审查吗？

[`16:50`](https://youtu.be/julbw1JuAz0?t=1010) 是的，绝对要审查。在 Anthropic，我们有非常严格的代码审查流程。即使代码是 Claude 写的，它仍然需要经过人工审查。我们有不同的审查级别。我们有 CI 检查。我们有 lint 规则。我们还有人工审查。所有这些层次共同确保代码质量。

[`17:10`](https://youtu.be/julbw1JuAz0?t=1030) 让我谈谈我个人的 Claude Code 体验。

[`17:15`](https://youtu.be/julbw1JuAz0?t=1035) 请说。

[`17:18`](https://youtu.be/julbw1JuAz0?t=1038) 我是 Claude Code 的重度用户，我看到很多人在 X 上分享类似的故事。但有些人觉得他们跟不上。你在 X 上关于这点的帖子引起了很多共鸣。你能谈谈这个吗？

[`17:35`](https://youtu.be/julbw1JuAz0?t=1055) 我理解那种感觉。技术变革的速度之快，让人感觉难以跟上。但重要的是要记住，每个人都在与同样的变化作斗争。关键是要保持好奇心和适应性。不要试图一次学习所有东西。小步前进，持续从经验中学习。

[`18:00`](https://youtu.be/julbw1JuAz0?t=1080) 你认为哪些技能现在更重要了？

[`18:05`](https://youtu.be/julbw1JuAz0?t=1085) 我认为沟通和解决问题等软技能变得更加重要。花时间理解问题，与利益相关者沟通，以及批判性思考解决方案的能力——这些是 Claude 无法替代的。纯粹编写代码的技能可能变得不那么有差异化，因为 Claude 也能做到。但知道要构建什么，以及为何要构建它——这仍然是人类的技能。

[`18:35`](https://youtu.be/julbw1JuAz0?t=1115) 你认为 Clauude Code 这样的工具是否在改变软件工程师的角色？

[`18:42`](https://youtu.be/julbw1JuAz0?t=1122) 绝对在改变。我认为软件工程师的角色正在从编写代码转变为从系统获取代码。我们基本上是 AI 的经理。我们设定方向，审查输出，并做出关于构建什么的高层次决策。我认为这是一件好事。它让工程师能够专注于更有趣的部分——设计和解决问题——而不是陷入编写样板代码的细节中。

[`19:05`](https://youtu.be/julbw1JuAz0?t=1145) 你对刚进入这个领域的人有什么建议？

[`19:10`](https://youtu.be/julbw1JuAz0?t=1150) 先学会基础知识。在依赖 Claude 帮你编写之前，理解编程的基本概念。然后开始使用工具，了解它们能做什么和不能做什么。关键是不要仅仅成为一个"提示工程师"——要成为一个使用 AI 来增强自身能力的真正的工程师。

[`19:40`](https://youtu.be/julbw1JuAz0?t=1180) 如何正确使用 Claude Code——秘诀是什么--或者说最大的坑是什么？

[`19:45`](https://youtu.be/julbw1JuAz0?t=1185) 给模型正确的上下文。不要给它太多信息，也不要给太少。开始时要小范围、聚焦。Claude Code 在任务范围明确时表现最好。当你给它一个模糊的提示比如"修复这个应用"时，它表现不佳。但如果你说"修复用户登录表单上的这个特定 bug，以下是堆栈跟踪"，它就会表现出色。所以提供的上下文越好，结果就越好。我注意到的另一件事是，人们只需尝试就能学到很多。很多人只是打开 Claude Code，尝试一件事，看看会发生什么。这是学习它的力量极限的最好方式。

[`20:20`](https://youtu.be/julbw1JuAz0?t=1220) 说到大型重构——Claude Code 是如何处理这些的？

[`20:25`](https://youtu.julbw1JuAz0?t=1225) Claude Code 在代理模式下非常擅长这个。它会规划需要做什么，然后逐个文件地进行更改。如果需要创建新文件，它会创建。如果需要在多个文件中搜索并替换模式，它也能做到。对于真正大规模的重构，你可能会需要多次运行 Claude Code，每次处理一部分。但即使如此，它也比我手动做快得多。

[`20:50`](https://youtu.be/julbw1JuAz0?t=1250) Claude Code 与 CI/CD 系统的集成如何？

[`20:55`](https://youtu.be/julbw1JuAz0?t=1255) Claude Code 与 GitHub 集成得很好。你可以让 Claude Code 审查拉取请求，提出更改建议，甚至直接修复问题。你可以在 CI 工作流中触发 Claude Code 来做代码审查或自动修复常见问题。这是我们看到很多团队在使用的。

[`21:20`](https://youtu.be/julbw1JuAz0?t=1280) Claude Code 如何处理你自己的代码库？它在编写代码时会审查自己的代码吗？

[`21:30`](https://youtu.be/julbw1JuAz0?t=1290) 是的，我们实际上使用 Claude Code 来审查由 Claude Code 编写的代码。我们在 CI 中有自动化代码审查，检查由 Claude Code 生成的代码的质量。这形成了一种反馈循环，模型从自己的输出中学习。

[`21:55`](https://youtu.be/julbw1JuAz0?t=1315) 你如何处理 Claude Code 中的安全性？例如，如果它修改了重要的系统文件呢？

[`22:00`](https://youtu.be/julbw1JuAz0?t=1320) 我们有多个安全层。第一层是权限系统——任何有副作用的操作都需要权限。第二层是我们可以配置"允许列表"和"阻止列表"，指定允许或禁止 Claude Code 运行哪些命令。第三层我们有运行时分类器来检测可疑活动。第四层是所有的操作都是可审计的——你可以看到 Claude Code 做过的每一件事。这是瑞士奶酪模型——多层的安全措施，任何漏洞被某一层捕获的概率都很高。

[`22:40`](https://youtu.be/julbw1JuAz0?t=1360) 你认为 Claude Code 的什么特性最被低估了？

[`22:45`](https://youtu.be/julbw1JuAz0?t=1365) 我认为最被低估的特性是它处理副项目的能力。很多人认为 Claude Code 适合主要的生产代码，但它也适合实验原型、学习新框架，甚至自动处理运维任务。看到人们用它做各种事情——从监控番茄植株到从损坏的硬盘中恢复照片——这太棒了。

[`23:10`](https://youtu.be/julbw1JuAz0?t=1390) 你能谈谈 Claude Code 是如何从 Sketch 开始的吗？从内部工具到产品发布的过程是怎样的？

[`23:15`](https://youtu.be/julbw1JuAz0?t=1395) 是的，Claude Code 最初是一个 side project。我觉得 Claude 作为结对编程伙伴会很好用。于是我开始在周末捣鼓。我建立了一个基本的循环——Claude 可以读取文件、写入文件和运行命令。我很快就意识到了它的潜力。我在公司内部展示了它，人们也很兴奋。于是我们决定作为内部工具来开发。它在 Anthropic 内部慢慢传播。然后我们意识到外部开发者可能也想要这个。我们经过一番讨论——关于安全、支持和策略——最终决定发布它。剩下的就是历史了。

[`23:55`](https://youtu.be/julbw1JuAz0?t=1435) Anthropic 内部有没有关于是否应该发布 Claude Code 的争论？

[`24:00`](https://youtu.be/julbw1JuAz0?t=1440) 有的，内部有激烈的争论。安全团队特别关注给予模型运行 bash 命令的权限。我们进行了长时间的讨论。最终，我们达成了共识：有了适当的安全措施，发布它是值得的。这并非一致同意，但这是经过深思熟虑的风险。

[`24:25`](https://youtu.be/julbw1JuAz0?t=1465) Claude Code 未来的路线图是什么？

[`24:30`](https://youtu.be/julbw1JuAz0?t=1470) 我们有很多令人兴奋的东西正在开发中。更好的代理能力，与更多工具的集成，更完善的权限和安全性。我们还在探索让 Claude Code 与其他代理协作的方式。但最重要的是，我们希望让 Claude Code 更有用，让更多人能够使用它。

[`24:55`](https://youtu.be/julbw1JuAz0?t=1495) 你认为 AI 编程工具的最终状态是什么？

[`25:00`](https://youtu.be/julbw1JuAz0?t=1500) 我认为最终状态是任何人都可以通过自然语言构建软件，而不需要知道如何编码。就像印刷机让识字变得普及一样，AI 编程工具让"构建软件"这个行为变得普及。不一定是"编程"——而是用软件解决问题。我认为这将开启一波新的创新浪潮，因为更多的人将能够构建他们需要的工具和产品。

[`25:30`](https://youtu.be/julbw1JuAz0?t=1530) 你对 Claude Code 的设计理念是什么？

[`25:35`](https://youtu.be/julbw1JuAz0?t=1535) 设计理念是增强而不是替代。我们不想取代开发者。我们想让他们更强大。所以我们围绕"人在回路中"的理念来设计 Claude Code。它是协作性的。它是透明的。它始终尊重用户的自主权。另一个核心原则是渐进式复杂度——用户可以从简单的提示开始，随着学习深入，可以开始使用更高级的功能，比如代理、自定义 slash 命令和钩子。

[`26:05`](https://youtu.be/julbw1JuAz0?t=1565) 你是如何保持密切关注开发者的实际体验的？

[`26:10`](https://youtu.be/julbw1JuAz0?t=1570) 我们自己使用产品。Claude Code 团队每天都使用它来构建 Claude Code。这是我们最重要的反馈来源。我们还密切监控用户反馈——GitHub issues、社交媒体、直接的用户对话。我们也在进行用户研究，比如采访重度用户以了解他们的工作流程和痛点。

[`26:40`](https://youtu.be/julbw1JuAz0?t=1600) 开发 Claude Code 的过程中，最让你惊讶的是什么？

[`26:45`](https://youtu.be/julbw1JuAz0?t=1605) 最让我惊讶的是人们使用它的各种不同方式。我们看到数据科学家、设计师、产品经理，甚至财务人员都在使用 Claude Code。我们本以为它主要对开发者有用。但令人惊讶的是，非技术用户也在寻找使用它的方式——通常是通过像 Claude Code 这样的自然语言界面来克服技术障碍。

[`27:15`](https://youtu.be/julbw1JuAz0?t=1635) 当别人问"用 Claude Code 编码是什么感觉"时，你怎么回答？

[`27:20`](https://youtu.be/julbw1JuAz0?t=1640) 就像是一个知道整个代码库的结对程序员，你不必解释所有背景信息。它就在那里，阅读代码，提出建议，并且编写代码的速度比你快得多。但它仍然尊重你作为团队领导的角色——你设定方向，做重要决策，它处理实现细节。

[`27:45`](https://youtu.be/julbw1JuAz0?t=1665) 你认为像 Claude Code 这样的工具会消灭初级开发者的角色吗？

[`27:50`](https://youtu.be/julbw1JuAz0?t=1670) 不，我认为它们会改变但不会消灭这些角色。初级开发者仍然需要学习基础知识，但他们将使用不同的工具来达到那里。就像印刷机没有消灭阅读，只是改变了教与学的方式一样。AI 编程工具不会消灭编程——它们会改变人们学习它的方式。

[`28:15`](https://youtu.be/julbw1JuAz0?t=1695) 你认为对于开发者来说，短期内最重要的技能是什么？

[`28:20`](https://youtu.be/julbw1JuAz0?t=1700) 批判性思维和问题解决。以及写出好的提示。这不是关于学会"完美提示"的神奇组合，而是关于清晰地沟通你想要什么。了解代码架构——知道在哪里进行更改，即使你不一定自己编写它们。还有适应性——因为技术变化太快，你最好准备好不断学习和适应。

[`28:50`](https://youtu.be/julbw1JuAz0?t=1730) 你提到"复习"很快——审查过程是什么样的？

[`28:55`](https://youtu.be/julbw1JuAz0?t=1735) 当我审查 Claude Code 的输出时，我通常在找一个信号，表明代码是否朝着正确的方向前进。我不再看每一个字符。我信任 Claude Code 能正确编写代码，但我会审查高层次的结构、架构决策，以及任何看起来可能有问题的地方。这是一种"基于信任的审查"——因为 Claude Code 已经证明了自己的可靠性，所以我不需要微观管理它。

[`29:25`](https://youtu.be/julbw1JuAz0?t=1765) 但是在模型崩溃或做出奇怪事情的情况下呢？你如何防范？

[`29:30`](https://youtu.be/julbw1JuAz0?t=1770) 我们有多层保护。我们有权限系统——它不能运行任意命令而不经许可。我们有 CI 检查。我们有代码审查。而且，模型本身也在改进——Claude 4.5 Opus 和其他新模型在遵循指令和保持一致性方面要好得多。这就像瑞士奶酪模型——任何单一漏洞被其中一层漏洞捕获的概率很高。

[`30:00`](https://youtu.be/julbw1JuAz0?t=1800) 开发者应该如何开始使用 Claude Code？你推荐什么工作流程？

[`30:05`](https://youtu.be/julbw1JuAz0?t=1805) 从小处着手。给它一个聚焦的任务，比如"为这个函数添加单元测试"或"重构这个模块"。在你对它的能力有信心之前，不要马上给它整个代码库。随着你使用越来越多，你将了解它擅长什么，不擅长什么。然后你可以逐渐扩展你要求它做的事情。

[`30:35`](https://youtu.be/julbw1JuAz0?t=1835) Claude Code 如何处理代码库中已有的代码？它是否尊重现有的模式？

[`30:40`](https://youtu.be/julbw1JuAz0?t=1840) 是的，Claude Code 在读取现有文件以理解代码风格和模式方面做得很好。然后它在生成新代码时模式匹配这些模式。所以它是相当有上下文意识的。它不只是生成风格不匹配的代码——它试图匹配代码库中已有的风格。

[`31:05`](https://youtu.be/julbw1JuAz0?t=1865) 最后，你对 Claude Code 的用户有什么建议？

[`31:10`](https://youtu.be/julbw1JuAz0?t=1870) 别怕尝试。很多人犹豫不决，因为他们担心 Claude Code 会做错事。但试试看——你可能会惊讶于它完成的事情。从小处着手，建立信任，然后扩大规模。我相信那些早点采用这些工具的人会拥有优势。
