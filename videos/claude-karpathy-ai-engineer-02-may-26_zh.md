## 演讲实录

### 引言

我们非常激动地迎来我们的第一位特邀嘉宾。他帮助构建了现代 AI，然后解释了现代 AI，偶尔还重新命名了现代 AI。他实际上在这个办公室里共同创立了 OpenAI。他是当年让 Tesla 的 Autopilot 真正工作起来的人。他有一种罕见的天赋，能让最复杂的技术变革既显得可及又显得必然。你们都因为他去年创造的"vibe coding"（氛围编程）一词而认识他。但就在过去几个月里，他说了一些更令人震惊的话——他说他从来没有像现在这样感到自己作为程序员如此落后。这就是我们今天要开始的话题。谢谢你，Andrej，欢迎你。

是的，你好。很高兴来到这里，为大家开场。

### "从未如此感到作为程序员落后"

好的。就在几个月前，你说你从未感到作为程序员如此落后。从你口中听到这句话尤其令人震惊。你能帮我们解读一下吗？这种感觉是令人兴奋还是令人不安？

当然是两者的混合。首先，和大家一样，我已经使用像 Claude Code 这样的代理工具一段时间了，大概从去年它刚出来的时候就开始用了。它在处理代码片段方面非常出色，但有时会出错，你需要修改它们，这还挺有用的。然后我要说，去年十二月是一个明确的转折点——当时我在休假，所以有更多时间。我想很多人也和我一样——我开始注意到，使用最新的模型，代码片段直接就能正确生成，然后我不断要求更多，它也一直正确生成，后来我甚至不记得上一次纠正它是什么时候了。然后我越来越信任这个系统，就这样我开始 vibe coding 了。

这是一个非常明显的转变。我想很多人实际上——我试图在 Twitter 或 X 上强调这一点——因为我认为去年很多人体验 AI 的方式还是把它当作 ChatGPT 的附属品。但你真的需要重新审视，特别是从去年十二月开始，因为事情已经发生了根本性的变化——尤其是这种代理式的连贯工作流真正开始发挥作用了。所以我想说的是，正是这种认识让我深入探索了这个无限副项目的兔子洞。我的副项目文件夹里塞满了各种随机的东西，我整天都在 vibe coding。所以大概是在去年十二月发生的变化，从那时起我一直在关注它的影响。

### Software 3.0：新的计算范式

你多次谈到 LLM 作为一台新计算机的观点。这不仅仅是更好的软件，而是一个全新的计算范式。Software 1.0 是显式规则，Software 2.0 是学习得到的权重，Software 3.0 就是现在这个。如果这真的是事实，那么一个团队在真正相信这一点后会如何以不同的方式构建产品？

是的。Software 1.0，我在编写代码；Software 2.0，我通过创建数据集和训练神经网络来进行编程。所以编程更像是安排数据集和一些目标以及神经网络架构。然后发生的事情是，如果你在足够大的任务集上训练这些 GPT 模型或 LLM——因为通过在互联网上训练，你实际上必须多任务处理数据集中所有的东西——这些模型在某种意义上变成了一种可编程的计算机。

所以 Software 3.0 是关于你的编程现在变成了提示，而上下文窗口中的内容是你对解释器（即 LLM）的杠杆，它正在解释你的上下文并在数字信息空间中执行计算。

我认为有几个例子真正让我明白了这一点。例如，当 OpenClaw 发布时，要安装 OpenClaw，你通常会期望这是一个 bash 脚本（一个 shell 脚本）。运行 shell 脚本安装 OpenClaw。但问题是，为了支持运行 OpenClaw 的各种平台和不同类型的计算机，这些 shell 脚本通常会膨胀得极其复杂。但你仍然被困在想要编写代码的 Software 1.0 世界中。实际上，OpenClaw 的安装说明是一段你要复制粘贴给代理的文本。基本上就是一个技能："复制粘贴这个给你的代理，它会安装 OpenClaw。"这之所以更强大，是因为你现在在 Software 3.0 的范式下工作——你不需要精确地说明设置的所有细节。代理有自己的智能，它打包起来，然后按照指令行事，查看你的环境、你的计算机，并执行智能操作来让一切正常工作，并在循环中进行调试。这要强大得多。所以这是一种完全不同的思考方式——什么是可以复制粘贴给你的代理的文本？这就是新的编程范式。

### MenuGen 和"本不该存在的应用"

另一个我想起来的例子，比刚才那个更极端，就是我在构建 MenuGen 的时候。MenuGen 的想法是：你去一家餐厅，他们给你菜单。通常没有图片。所以我完全不知道这些东西是什么——大概 30% 的东西我不知道是什么，有时是 50%。所以我想拍一张餐厅菜单的照片，然后得到这些菜品的通用图片。

我用 vibe coding 构建了这个应用：你可以上传照片，它会处理所有事情，运行在 Vercel 上，它基本上会重新渲染菜单，给你展示所有菜品，并使用图像生成器来 OCR 所有不同的标题，用图像生成器获取它们的图片，然后展示给你看。

然后我看到了 Software 3.0 版本的实现——这让我震惊——基本上就是拍张照片，交给 Gemini，说"用 Nanobanana 把这些东西叠加到菜单上。"然后 Nanobanana 直接返回了一张和我拍的完全一样的菜单图片，但它在像素中实际渲染了菜单上的不同菜品。这让我震惊，因为实际上我整个 MenuGen 都是多余的。它工作在旧的范式下。那个应用本不该存在。

Software 3.0 的范式要原始得多。你的神经网络在做越来越多的工作，你的提示或上下文只是图片，输出也是图片，中间完全不需要任何应用。所以人们需要重新思考——不要用已有的范式来工作，不要仅把它看作是已有事物的加速。现在有了新的事物可以实现。

回到你的编程问题，这甚至不仅仅是——我认为这也是一个用旧思维思考的例子——这不仅关乎编程和编程变得更快。这是更广泛的信息处理，现在可以自动化了。所以这甚至不仅仅是代码的问题。以前的代码工作在结构化数据之上，对吧？你在结构化数据上编写代码。但例如我的 LLM 知识库项目——基本上就是让 LLM 为你的组织或为你个人创建 wiki——这甚至不是一个程序。这在以前是不可能存在的，因为没有代码能根据一堆事实创建知识库。但现在你只需要拿这些文档，以不同的方式重新编译它们，重新组织，创造出对数据重新解读的新鲜有趣的东西。这些都是以前不可能实现的新事物。所以我认为这是我一直在试图回归的观点——不仅是我们可以更快地做已经存在的事情，而且我认为还有新的机会去实现以前根本不可能的事情，我几乎认为后者更令人兴奋。

### 展望 2026 年及以后

我喜欢你刚才讲的 MenuGen 演进和二分法。如果进一步推演，2026 年对应的是什么？就像 90 年代建网站、2010 年代建移动应用、上一个云时代建 SaaS——什么东西在事后看来会显得完全明显，但在今天大部分还没有被构建出来？

回到菜单的例子，很多这样的代码本就不该存在，应该让神经网络来完成大部分工作。我认为推演的结果看起来会非常奇怪，因为你基本上可以想象在某种意义上的完全神经计算机。你输入原始视频——想象一个设备，它接收原始视频或音频，输入到一个神经网络中——然后使用扩散模型渲染出一个在那一刻独一无二的 UI。

我有点觉得在计算的早期，人们其实不确定计算机会是计算器那样的，还是神经网络那样的。在 50 年代和 60 年代，哪条路会胜出并不明朗。当然，我们走的是计算器的道路，最终构建了经典计算，而神经网络目前是在现有计算机上虚拟化运行的。但我认为很多事情会翻转，神经网络会成为宿主进程，CPU 成为协处理器。我们已经看到神经网络的智能计算将占据主导地位，成为 FLOPs 的主要消耗。所以你可以想象一些非常奇怪和陌生的事情：神经网络在做大部分繁重的工作，它们使用工具——这种历史上的附属功能——来处理某些确定性任务。但真正主导的是这些神经网络。所以你可以想象非常陌生的事物作为推演结果，但我认为我们会一步一步地到达那里。

### 可验证性与锯齿状智能

我想聊聊可验证性这个概念——AI 会更快地自动化那些输出可以被验证的领域。如果这个框架是对的，哪些工作会以超出人们预期的速度加速，而哪些我们以为安全的职业实际上是非常可验证的？

我花了一些时间写关于可验证性的文章。传统计算机可以轻松自动化你能用代码指定的事情，而最新一轮的 LLM 可以轻松自动化你能验证的事情——在某种意义上。因为这些模型的工作原理是：当前沿实验室训练 LLM 时，它们处于巨大的强化学习环境中。它们获得验证奖励，然后由于模型的训练方式，它们最终会进步并创造出这些锯齿状的实体，在可验证领域如数学和代码等方面能力突出——而在非这些领域的方面则表现粗糙、有些边缘不齐。

所以我写关于可验证性的原因，是我试图理解为什么这些东西如此锯齿状。部分原因与实验室如何训练模型有关，但我认为部分原因也与实验室的焦点有关，以及他们碰巧放在数据分布中的内容。因为有些事情在经济上更有价值，最终创造了更多的环境，因为实验室希望在这些设置中工作。所以我认为代码是一个很好的例子。可能还有很多可验证的环境是实验室可以想到的，但因为它们不太有用而没有被纳入混合。

最大的谜题——有一段时间最受欢迎的例子是"'strawberry' 里有多少个字母"，模型会著名地答错，这就是锯齿状的一个例子。模型现在已经修补了这个。但新的问题是："我想去洗车场洗车，距我 50 米。我应该开车还是走路？"最先进的模型今天会告诉你走路，因为太近了。最先进的 Opus 4.7 怎么可能同时重构一个 10 万行的代码库，或发现零日漏洞，却又告诉我要走路去洗车场？这太疯狂了。

无论这些模型保持多么锯齿状，它都表明：第一，可能有些地方不太对劲；第二，你需要稍微保持人在循环中，你需要把它们当作工具，你需要关注它们在做什么。所以我所有关于可验证性的写作，简而言之，就是试图理解为什么这些东西是锯齿状的。有没有什么模式？我认为是"可验证性"加上"实验室在意"的某种组合。

也许还有一个有启发性的轶事：从 GPT-3.5 到 GPT-4，人们注意到国际象棋进步了很多，很多人认为"哦，这只是能力在进步"——但实际上更可能是因为大量的国际象棋数据进入了预训练集，仅仅因为它出现在数据分布中，模型的进步就比默认情况下大得多。所以 OpenAI 的某个人决定加入这些数据，然后你就看到了一个能力峰值大幅提升。

这就是我强调这个维度的原因：我们在一定程度上受制于实验室在做什么，以及他们碰巧在混合中放入什么。你必须实际探索他们给你的这个东西，它没有说明书。它在某些设置下有效，但在其他设置下可能无效。如果你在 RL 所覆盖的回路中，你会飞得很快。如果你在数据分布之外的回路中，你就会挣扎，你需要弄清楚你的应用处于哪个回路。如果你不在这些回路中，那你真的需要考虑微调和自己做一些工作，因为 LLM 不一定能开箱即用地给出答案。

### 给创始人的建议

如果你今天是一位创始人，正在考虑创办公司，你试图解决一个你认为可处理的问题，一个可验证的领域，但你环顾四周，心想"天哪，实验室已经开始在最明显的领域——数学、编程等——达到逃逸速度了。"你会给在座的创始人什么建议？

我认为在当前范式下，可验证性使事情变得可处理，因为你可以投入大量的 RL。所以一种看法是，即使实验室没有直接关注它，这一点仍然成立。如果你处在一个可验证的环境中，你可以创建 RL 环境或示例，那么这实际上为你自己进行微调创造了条件，你可能会从中受益。这是从根本上就有效的技术。如果你有大量多样化的 RL 环境数据集，你可以使用你喜欢的微调框架，拉动杠杆，得到实际上相当不错的结果。

我确实认为有一些非常有价值的强化学习环境是人们可以想到的，但不在实验室的焦点范围内。我不想在这里给出答案，但确实存在一个我认为非常有价值的领域。抱歉，我不是故意在台上打哑谜，但确实有一些这样的例子。

另一方面，你认为什么东西看起来可以自动化但实际上只是表面现象？

我认为最终几乎所有事情都可以在一定程度上变得可验证——有些事情比其他事情更容易。因为即使是写作这样的事情，你也可以想象由一个 LLM 评判委员会来评判，大概可以从这种方法中得到合理的结果。所以这更多是关于什么是容易的，什么是困难的。我认为最终一切都是可以自动化的。

### Vibe Coding 与 Agentic Engineering

去年你创造了"vibe coding"这个词，今天我们处于一个感觉更加严肃的世界——更多的 agentic engineering。你认为两者之间的区别是什么，你会如何称呼我们今天所处的阶段？

是的。我会说 vibe coding 是关于提升每个人在软件方面的下限。下限提高了，每个人都可以 vibe coding 任何东西，这很了不起，难以置信。但 agentic engineering 是关于保持以前专业软件的质量标准。你不能因为 vibe coding 而引入漏洞。你仍然对你的软件负责，就像以前一样。但你能否更快？剧透：你可以。但如何正确地做到这一点？所以对我来说，agentic engineering——我这么称呼它，因为我确实认为这是一门工程学科——你拥有这些代理，它们是这些锯齿状的实体。它们有些容易出错，有点随机，但极其强大。你如何协调它们以在不牺牲质量标准的情况下更快？正确做好这件事就是 agentic engineering 的领域。

所以我把它们看作是不同的——一个是关于提升下限，另一个是关于推高上限。我看到的是，agentic engineer 的能力上限非常高。人们过去谈论 10 倍工程师——我认为这被放大得更多了。10 倍不是你获得的加速。从我目前的视角来看，擅长这个的人似乎远超 10 倍。

### AI 原生编码是什么样的

Sam Altman 去年在 AI Engineer 大会上说的一件令人难忘的事情是，不同世代的人使用 ChatGPT 的方式不同。如果你 30 多岁，你把它当作 Google 搜索的替代品。但如果你十几岁，ChatGPT 是你通往互联网的门户。这在今天的编码中有什么对应的现象？如果我们观察两个人使用 OpenClaw、Claude Code、Codex 编码——一个人你认为很平庸，另一个人你认为完全 AI 原生的——你会如何描述他们的区别？

我认为就是充分利用可用的工具——利用它们的所有功能，投入到自己的设置中。就像以前所有的工程师都会充分利用他们使用的工具——无论是 Vim 还是 VS Code，现在是 Claude Code 或 Codex——投入时间优化你的设置，利用所有可用的工具。我认为就是这样。

一个相关的想法——很多人现在可能正在招聘这个，因为他们想雇佣强大的 agentic engineer。我确实认为大多数人还没有重构他们的招聘流程来评估 agentic engineer 的能力。如果你在出谜题让人解，这仍然是旧的范式。我认为招聘必须看起来像：给我一个真正的大项目，看这个人如何实现这个大项目。比如，让我们为代理写一个 Twitter 克隆，把它做得非常好，非常安全，然后让一些代理在这个 Twitter 上模拟一些活动，然后我用 10 个 Codex 5.4x 来试图攻破你部署的网站，它们试图攻破它，而它们应该无法攻破。所以可能看起来是这样的。观察人们在这种环境下构建更大的项目并利用工具，这大概是我主要关注的方式。

### 品味、判断力和人在循环中的作用

随着代理做越来越多的事情，你认为什么样的人类技能变得更有价值，而不是更少？

目前答案是，代理有点像实习生这种实体。值得注意的是，你基本上还是要负责审美、判断力、品味，以及一定的监督。

我最喜欢的关于代理奇怪之处的例子是——对于 MenuGen，你用 Google 账号注册，但用 Stripe 账户购买积分，两者都有电子邮件地址。我的代理实际上尝试过，当你购买积分时，它用 Stripe 的电子邮件地址关联到 Google 的电子邮件地址——就像没有一个持久的用户 ID。对人类来说，它试图匹配电子邮件地址，但你可以为你的 Stripe 和 Google 使用不同的电子邮件地址，这样资金就无法关联起来。这就是这些代理仍然会犯的错误——比如，为什么要用电子邮件地址来交叉关联资金？它们可以是任意的。你可以使用不同的电子邮件。这是一个非常奇怪的做法。

所以我认为人们必须负责这个规格、这个计划。我实际上甚至不太喜欢计划模式。显然它非常有用，但我认为这里有更一般的东西：你必须与你的代理一起设计一个非常详细的规格——也许基本上是文档——然后让代理去编写，你负责监督和顶层类别的把控，但代理做了大量底层工作。所以你不需要关心一些细节。

另一个例子是关于神经网络中的数组或张量。PyTorch 和 NumPy 以及所有不同的——Pandas 等——所有不同的 API 细节中有大量细节。我已经忘记了 keep_dims 和 keep_dim 的区别，或者它是 `dim` 还是 `axis`，reshape 还是 permute 还是 transpose。我不再记得这些东西了。因为你不需要记住。这是由实习生处理的细节，因为他们有非常好的记忆力。但你仍然需要知道，例如，存在一个底层的 tensor，存在一个底层的 view，然后你可以操作同一个存储的不同视图，或者你可以有不同的存储，后者效率更低。所以你仍然需要理解这些东西在做什么以及一些基本原理，这样你就不会不必要地复制内存等。但是 API 的细节现在都交给代理了。所以你负责品味、工程、设计——以及确保它有意义，确保你要求的是正确的事情。比如，好的，这些必须是唯一的用户 ID，我们将把所有东西关联到上面。所以你做一些设计和开发工作，而工程师（代理）做填空。这就是我们目前的状态。

你认为随着时间的推移，这种品味和判断力会变得不那么重要吗，还是上限会不断提升？

我希望它会改善。我认为它现在没有改善的原因，再次强调，它不是 RL 的一部分。可能没有审美成本或奖励，或者还不够好之类的。我确实认为，当你真正看代码时，有时我会有点心塞，因为它不总是超级棒的代码。它非常臃肿，有很多复制粘贴，有笨拙且脆弱的抽象，它能工作但真的很粗糙。我希望未来模型能改进这一点。

一个好的例子是 microGPT 项目，我试图将 LLM 训练简化到尽可能简单。模型讨厌这个。它们做不到。我试着不断提示 LLM 让它简化、再简化，但它就是做不到。你感觉你处于 RL 回路之外。就像拔牙一样。它不像光速那样高效。所以我确实认为人们仍然负责这部分。但并没有什么根本性的东西阻止它。只是实验室还没有做到这一点，差不多就是这样。

### 动物 vs 幽灵：理解 LLM 是什么

我想回到这个锯齿状智能的概念。你写了一篇发人深省的文章，关于动物与幽灵。核心思想是，我们不是在建造动物，而是在召唤幽灵。这些是锯齿状的智能形式，由数据和奖励函数塑造，而不是由内在动机、乐趣、好奇心或赋权塑造——这些是通过进化而来的东西。为什么这个框架很重要，它实际上会如何改变你构建、部署、评估甚至信任它们的方式？

我写这篇文章是因为我试图理解这些东西究竟是什么。因为如果你对它们是什么或不是什么有好的模型，你就能更有效地使用它们。我不确定它是否真的有实际力量。我认为这有点哲学思考。但这只是接受一个事实：这些东西不是动物的智能。如果你对它们大喊大叫，它们不会工作得更好或更差——这没有任何影响。一切都只是统计模拟回路，其基底是预训练（所以是统计学），然后 RL 叠加在上面，所以它在一定程度上增加了倾向。也许这只是一种心态问题——我面对的是什么，什么可能有效或无效，如何修改它。但我实际上没有"这里有五个让你的系统更好的明显方法"。更多的是对它保持怀疑，并随着时间的推移去搞清楚。这就是起点。

### 代理原生基础设施

好的，你深度参与代理的工作——不仅仅聊天——它们有真正的权限，有本地上下文，实际代表你采取行动。当我们都开始生活在那个世界时，世界会是什么样子？

我想很多人可能对代理原生环境的样子感到兴奋。一切都需要重写。一切都仍然是为人类编写的，需要被改变。我大部分时间在使用不同的框架或库时，它们的文档仍然是为人类编写的。这是我最喜欢的小烦恼。为什么人们还在告诉我该做什么？我什么都不想做。我应该复制粘贴什么给代理？每次有人告诉我"去这个 URL"之类的话，我就会想啊啊啊。

每个人都兴奋于如何将需要完成的工作分解为世界上的传感器和执行器。如何让它变成代理原生的？基本上，首先为代理描述它。然后围绕对 LLM 非常可读的数据结构进行大量自动化。

对于 MenuGen，著名的是当我写关于 MenuGen 的博客文章时——很多麻烦甚至不是写 MenuGen 的代码，而是部署在 Vercel 上，因为我必须处理所有这些不同的服务，必须把它们串起来，必须去它们的设置和菜单，配置我的 DNS，这太烦人了。这是一个很好的例子：我希望 MenuGen 可以让我给 LLM 一个提示"构建 MenuGen"，然后我就不需要碰任何东西了，它就以相同的方式部署在互联网上。我认为这将是一个很好的测试，检验我们很多基础设施是否变得越来越代理原生。

最终，我认为我们正在走向一个世界，其中人和组织都有代理代表。"让我的代理和你的代理谈谈"来解决我们会议的一些细节之类的事情。所以我认为这大致就是未来的方向。

### 教育：外包思考，但不能外包理解

我想我们必须以教育问题来结束。因为你可能是世界上最擅长将复杂技术概念简单化的人之一，并且在如何设计围绕它的教育方面有深刻的思考。当智能变得廉价，我们进入 AI 的下一个时代时，还有什么值得深入学习？

最近有一条推文让我震惊，我几乎每隔一天都会想到它。大意是：**"你可以外包你的思考，但你不能外包你的理解。"**

我认为这说得非常好。因为我仍然系统的一部分，我仍然需要某种方式——信息仍然需要进入我的大脑——我感觉我成了一个瓶颈，即使只是在了解我们在构建什么、为什么值得做、如何指导我的代理等方面。所以我确实认为，最终必须有东西来指导思考和处理，而这在根本上仍然受到理解的限制。

这也是为什么我对所有 LLM 知识库感到非常兴奋的原因之一——因为我感觉这是我处理信息的一种方式。每当我看到对信息的另一种投影时，我总觉得能获得新的洞察。所以对我来说，它只是很多提示，用于对某些固定数据进行合成数据生成。每当我一篇文章，我都非常享受——我的 wiki 正在从这些文章中构建起来，我喜欢问关于各种事情的问题。我认为这些工具在某种意义上最终是增强理解的工具。而这仍然是一个瓶颈，因为如果你——因为 LLM 当然不擅长理解，你仍然独特地负责这件事。所以这方面的工具，我认为，是非常有趣和令人兴奋的。

我很高兴几年后能再次回到这里，看看我们是否已经完全被自动化出这个循环，以及它们是否也能处理好理解。非常感谢你加入我们，Andrej。我们真的很感激。
