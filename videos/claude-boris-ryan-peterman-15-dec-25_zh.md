## 采访实录

[`0:00`](https://youtu.be/L9_s8M3_fNI?t=0) Boris Cherny 是 Claude Code 的创建者。在加入 Anthropic 之前，他是 Meta 的工程经理，拥有硬核工程的资历。他修复了 Facebook 上最古老的 bug 之一——一个 11 年之久的 bug。我们从这里开始，听听他是如何追踪找到它的。

[`0:19`](https://youtu.be/L9_s8M3_fNI?t=19) 我在 Facebook 工作的时候。当时我们在做一个新功能，我们需要从 Android 手机向 iOS 手机发送一个网络请求。这个请求需要包含一个参数，还有一个签名，以便你验证这个请求是合法的。我们一切就绪，但签名不匹配。至于为什么签名不匹配，即使所有参数都一致，我们仍然搞不明白。然后我们发现这个请求和响应之间有几微秒的延迟。在那一瞬间，手机的 DNS 记录可能已经改变了。而且我们用来计算签名的网络库，和你手机上用来验证的库，它们解析 IPv6 记录的顺序不同，这就是我们的一个签名不匹配的原因。所以是有道理的。解决方案是不在签名中包含 DNS 记录。几千行 diff，删除了很多代码。然后这个 bug 就修好了。

[`1:33`](https://youtu.be/L9_s8M3_fNI?t=93) 11 年之久的 bug。

[`1:36`](https://youtu.be/L9_s8M3_fNI?t=96) 是啊，很不错的 bug。

[`1:42`](https://youtu.be/L9_s8M3_fNI?t=102) 太棒了。所以今天我们和 Boris 在一起，他是 Claude Code 的创建者。我真的很期待这次对话。我有很多问题想问你。我认为你是我认识的少数几个，在 AI 革命中不仅没有变得不那么高效，反而变得更高效的人。很多人在努力让 AI 帮他们做更多事情。而你的效率不降反升——考虑到你有博客写作、会议演讲，以及大量其他的事情。所以我今天真的很想深入探讨一下。谢谢你接受邀请，Boris。

[`2:08`](https://youtu.be/L9_s8M3_fNI?t=128) 谢谢你邀请我，Ryan。

[`2:10`](https://youtu.be/L9_s8M3_fNI?t=130) 我们从你的背景开始。你写了第一本 TypeScript 书。曾在 Facebook 工作，也做过一些创业公司。现在你是 Claude Code 的创建者和负责人。你经常提到编码对你的实用性，而不是因为你对它充满热情。你能谈谈这种"编码是实用的"的理念，以及这在你的职业生涯中如何表现出来？

[`2:26`](https://youtu.be/L9_s8M3_fNI?t=146) 是的。我十几岁的时候开始编码，因为我在 eBay 上卖宝可梦卡，我意识到如果我用 blink 标签，我就能卖更多钱。这非常实用。后来在学校里，我给同学们编写数学解题器，这样我们就能在数学考试中取得更好的成绩。一直都非常实用。后来在大学里，学习经济学，然后辍学创业。编码始终是我达到目的的手段。我从不认为编码是一种艺术形式。它非常实用。这是一种构建对人们有用的东西的方式。我认为这种态度贯穿了我的整个职业生涯。这也是我最终来到 Anthropic 的原因。我来到 Anthropic 是因为我看了很多 sci-fi，我开始担心 AI 的风险。但我也看到 AI 的巨大潜力。所以我加入 Anthropic 是为了帮忙确保 AI 的发展方向是好的。

[`3:24`](https://youtu.be/L9_s8M3_fNI?t=204) 我想谈一谈你作为技术专家的成长历程。你提到过寻求"疯狂的责任"——尽可能承担巨大的责任，即使你不确定自己能否应对。这是你自然就有的想法，还是随着时间的推移而习得的？

[`3:41`](https://youtu.be/L9_s8M3_fNI?t=221) 我认为这是随着时间的推移而习得的。我不认为我在早期职业生涯中就提出要承担巨大的责任。我认为这是一个逐渐的过程。你开始承担越来越多的责任，你意识到你可以处理它。然后你觉得自己准备好承担更多了。最终你达到了一个点，你实际上在主动寻求巨大的责任，因为你知道那才是你学习和成长最快的方式。当你处于一个没有太多责任的位置时，你无法学到那么多。在一个你可以做决定、它们会产生实际后果的位置上，你学得最多。所以我认为寻求责任是加速成长的好方法。

[`4:22`](https://youtu.be/L9_s8M3_fNI?t=262) 你提到过，将你与其他人区分开来的一件事是你愿意处理模糊性。你能谈谈模糊性以及你如何应对它吗？

[`4:32`](https://youtu.be/L9_s8M3_fNI?t=272) 是的。我认为软件工程中的很多工作都是相当明确的——你有一个任务，它被分解成子任务，你只需要实现它。但真正有趣的工作，也是价值最高的地方，是模糊的地方。没有人真正知道应该构建什么，或者应该如何处理某个问题。能够进入那个空间，理清头绪，并找出解决方案——这是非常宝贵的技能。我认为处理模糊性的关键只是开始尝试。不要等着有人给你完美的答案。开始尝试一些东西。做一些原型。收集数据。从那里迭代。你很快就会发现什么可行，什么不可行。

[`5:10`](https://youtu.be/L9_s8M3_fNI?t=310) 说到模糊性——Claude Code 是一个很好的例子，它从一个模糊的想法开始。你能谈谈你是如何有了这个想法，以及你在 Anthropic 内部最终将其变成一个产品的过程吗？

[`5:24`](https://youtu.be/L9_s8M3_fNI?t=324) 是的。当我加入 Anthropic 时，我原本在做平台和基础设施方面的工作。但我在业余时间摆弄 Claude，我意识到如果 Claude 能读取我的文件系统、写入文件并运行命令，那么它可以成为一个令人难以置信的编程助手。于是我开始在这个想法上 hack。第一个版本非常粗糙——只是一个 Python 脚本，在循环中调用 API。但即使在那时，我也看到了巨大的潜力。我在公司内部展示了一下，人们很兴奋。大约在同一时间，我们有另一名工程师在做类似的事情。于是我们合并了我们的努力。经过几次迭代，它变成了 Claude Code。但一开始，它非常模糊。只是一个"如果 Claude 能帮我编码会怎样"的想法。我们通过尝试东西、看什么有效、什么无效，逐渐理清了它。

[`6:20`](https://youtu.be/L9_s8M3_fNI?t=380) 你认为 Claude Code 中最酷的技术创新是什么？

[`6:25`](https://youtu.be/L9_s8M3_fNI?t=385) 我认为在安全方面我们做了很多很酷的事情。权限系统——我们能够将模型的安全性与人类监督结合起来的方式很酷。特别是在安全和保障方面采用的瑞士奶酪模型——我们有多层保护，因此漏洞被其中某一层捕获的概率很高。另一个很酷的事情是我们处理代码搜索的方式。我们尝试了 RAG（检索增强生成）和本地向量数据库，但最终我们发现，仅使用 glob 和 grep 的代理搜索效果最好。这是一个很好的例子，有时最简单的解决方案就是最好的。

[`7:00`](https://youtu.be/L9_s8M3_fNI?t=420) 我们来谈谈模型改进的速度。你提到过，与旧模型一起工作的想法可能不适用于新模型。你能详细说说吗？

[`7:10`](https://youtu.be/L9_s8M3_fNI?t=430) 是的，这是最棘手的事情之一。当 Opus 4.5 发布时，突然之间，许多以前 Claude Code 不擅长的事情变得很擅长了。而一些以前有效的技术变得不再必要。你必须始终带着初学者的心态。因为在旧世界里，如果有人提出了一个过去尝试过但没成功的想法，人们会说"我们试过了，没用"。但现在，模型每几个月就会显著改进。所以六个月前失败的想法，今天可能完全可行。你必须愿意不断重新审视旧想法。

[`7:48`](https://youtu.be/L9_s8M3_fNI?t=468) 你推荐给开发者的最佳资源是什么，如果你想更深入地了解 Claude Code 及其工作方式？

[`7:55`](https://youtu.be/L9_s8M3_fNI?t=475) 我们有很多资源。GitHub 仓库有示例，文档网站有全面的指南。但一个真正被低估的资源是 Claude Code 本身——你可以直接问它，"Claude Code，给我解释一下工作流是如何设置的"或"你在编写代码时在使用什么工具"。它是自文档化的。此外，我们还开源了一大块 Claude Code，因此你可以在 GitHub 上浏览代码库，了解其内部工作原理。

[`8:30`](https://youtu.be/L9_s8M3_fNI?t=510) 你对刚开始使用 Claude Code 的人的有什么建议？

[`8:35`](https://youtu.be/L9_s8M3_fNI?t=515) 从小处着手。给它像"为这个函数添加单元测试"或"重构这个组件"这样简单的任务。在让它处理更大的任务之前，先在小任务上建立信任。还要密切注意它给你的上下文——Claude Code 打印出它正在做什么以及为什么。使用这些信息来了解它。而且不要害怕尝试不同的提示，看看什么有效。

[`9:05`](https://youtu.be/L9_s8M3_fNI?t=545) 我们收到了很多关于"软件工程中 AI 将取代我们吗？"的问题。你对此怎么看？

[`9:12`](https://youtu.be/L9_s8M3_fNI?t=552) 我认为这种担忧被夸大了。Claude Code 放大了工程师的能力——它不会取代他们。就像印刷机没有取代抄写员——它让他们成为了作家和作者，而且整个市场扩张了。同样的事情也会发生在编程上。编写代码的实际行为可能会变得不那么值钱，但知道要构建什么、为什么构建以及如何将它整合到更大的系统中，这些技能将变得更加宝贵。软件工程正在从"编写代码"转变为"从系统中获取代码"。这是一个根本性的转变。

[`9:52`](https://youtu.be/L9_s8M3_fNI?t=592) 关于未来的最后想法是什么？

[`9:55`](https://youtu.be/L9_s8M3_fNI?t=595) 我认为我们正处在一个真正非凡的时刻。那些拥抱这些工具的人将会处于难以置信的有利地位。最重要的技能是适应能力，愿意学习，和初学者的心态。而且我认为，最好的日子就在前方。

[`10:20`](https://youtu.be/L9_s8M3_fNI?t=620) 太棒了。非常感谢你，Boris。这是一次非常棒的谈话。

[`10:25`](https://youtu.be/L9_s8M3_fNI?t=625) 谢谢你，Ryan。
