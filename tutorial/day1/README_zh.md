# 第 1 天 — 与 Claude Code 的第一次对话

[返回第 0 天（设置）](../day0/README.md)

---

你已经安装了 Claude Code。现在呢？本指南带你了解使用它的三个层次——每一层都让你对 Claude **如何**完成工作有更多的控制。

可以把它想象成雇佣一个人：
1. **提示** = 在街上向陌生人问路
2. **代理** = 雇佣一个总是以特定方式做事的专家
3. **技能** = 该专家为特定任务接受过特定培训

---

## 层次 1：提示（直接问）

> 🧠 **把它想象成**给一个博学的朋友发短信。你问"卡拉奇天气怎么样？"他们会给你一个*答案*——但你不知道他们是否查了天气应用、看了窗外，还是只是凭记忆猜测。

打开终端输入 `claude`。你现在处于对话中。试试输入：

```
卡拉奇的天气怎么样？
```

Claude 会回答——但它**如何**回答是不可预测的。它可能会：
- 从训练数据中提取（可能已过时）
- 搜索网络（如果网络工具可用）
- 给你一个一般性答案，而非实时数据

对于快速提问，这完全没问题！但如果你需要**一致、可靠的结果**，仅靠提示是不够的。

### 提示适合的场景

- 询问关于你的代码库的问题（"这个文件是做什么的？"）
- 编写或编辑文档（"重写这封邮件，让它听起来更专业"）
- 头脑风暴想法（"为这个活动给我 5 个主题行"）
- 解释事物（"像我不是开发者一样解释这个错误信息"）

### 局限性

每次你问"天气怎么样？"，Claude 获取数据的方式可能不同——或者根本不获取真实数据。无法保证它两次使用相同的来源或方法。

## 层次 2：代理（专家）

**代理**是 Claude 扮演特定角色——就像分配一个职位头衔。

> 🧠 **把它想象成**一个餐厅厨房。没有代理的话，你走进一个陌生的厨房喊"给我做意面！"——听到的人可能会煮方便面，或者做一顿五道菜的意大利餐。有了代理，你雇佣了一个**意面厨师**，其工作描述说：*"始终使用新鲜食材，始终煮到弹牙，始终以同样的方式摆盘。"*现在你确切知道每次能得到什么。

以下是同样的思路应用于 Claude：

> **没有代理：** 你问 Claude"迪拜天气怎么样？"
> 它可能会检查训练数据、搜索网络或做出最佳猜测。你不知道它会做什么。
>
> **有代理：** 一个 `weather-agent` 有清晰的工作描述：
> *"始终检查迪拜的 Open-Meteo API。始终以特定的格式返回温度。"*
> 同样的问题，同样的方法，每次都一样。

### 本仓库中的真实示例

本仓库有一个 `weather-agent`——它的全部工作就是获取迪拜的温度。以下是它与仅提示的区别：

| | 提示 | 代理 |
|---|---|---|
| **来源** | 可能是任何地方 | 始终是 Open-Meteo API |
| **位置** | Claude 随意选择 | 始终是迪拜（纬度：25.2，经度：55.3） |
| **格式** | 随机的段落 | 清晰的温度 + 单位 |
| **一致性** | 每次都不同 | 每次都一样的方法 |

### 要点

代理给你带来**可预测性**。同样的问题 → 同样的方法 → 同样的质量。这就是优势——不是代理更聪明，而是它们**一致**。

## 层次 3：技能（培训）

**技能**是代理（或 Claude 本身）可以使用的一种特定能力。

> 🧠 **把它想象成**新员工的培训手册。当有人加入你的团队时，他们有一个角色（代理），但他们也会经历特定的培训模块——如何使用 CRM，如何写提案，如何主持站立会。每个培训模块都是一个**技能**。角色告诉他们*是什么*；技能告诉他们*如何*做特定的事情。

现在想想一个真实的人：

> **Shayan** 有很多技能：
> - 工程技能——能写代码
> - 游戏技能——了解游戏机制
> - 阅读技能——能消化和总结长文档
>
> 每种技能都有自己的知识和方法。Shayan 在合适的任务中使用合适的技能。

Claude 的工作方式相同。`weather-agent` 有一个名为 `weather-fetcher` 的技能：

- **代理**（`weather-agent`）= 职位为"天气记者"的人
- **技能**（`weather-fetcher`）= 关于*如何*获取天气数据的特定培训

技能包含精确的指令：
1. 调用这个特定的 API URL
2. 从响应中的这个特定字段提取温度
3. 以这个特定格式返回

### 为什么要把代理和技能分开？

因为**一个代理可以有多种技能**，而且**一种技能可以被多个代理使用**。

例如，想象你创建：
- 一个 `daily-report-agent`，用于总结你的一天
- 它可以使用 `weather-fetcher` 技能（天气）+ `calendar-reader` 技能（会议）+ `email-summarizer` 技能（邮件摘要）

技能是可重用的构建块。代理是使用它们的人。

## 整合起来

以下是完整的画面：

```
层次 1：提示
你 → "天气怎么样？" → Claude 以某种方式解决
                                （不可预测的方法）

层次 2：代理
你 → 天气代理 → 始终使用相同的方法
                      （可预测的方法）

层次 3：技能
你 → 天气代理 → 使用 weather-fetcher 技能
                      （具有特定指令的可预测方法）
```

每个层次增加更多控制：

| 层次 | 你控制的内容 | 最适合 |
|-------|-----------------|----------|
| **提示** | 问题 | 快速的一次性问题 |
| **代理** | 问题 + 谁来回答 | 可重复的任务 |
| **技能** | 问题 + 谁来回答 + 如何做 | 关键工作流 |
